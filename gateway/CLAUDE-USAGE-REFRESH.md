# Claude 사용량 인증 갱신 및 캐시

Claude 사용량은 공식 OAuth usage 응답을 읽으며 모델 추론 요청을 보내지 않습니다.

## 자동 처리

- 저장된 access token이 만료됐거나 usage API가 HTTP 401을 반환하면 공식 Claude CLI 초기화를 한 차례 시도합니다.
- CLI에는 stream-json `initialize` control 요청만 보냅니다. user prompt는 보내지 않습니다. 도구·MCP·사용자 커스터마이징을 비활성화하고 세션을 저장하지 않습니다.
- refresh token 회전과 인증정보 저장은 공식 CLI에 맡깁니다. Gateway가 인증정보 파일을 직접 덮어쓰지 않습니다.
- 초기화 성공만으로 갱신됐다고 판단하지 않습니다. 인증정보를 다시 읽고 사용량 GET 응답까지 확인합니다.
- 실패하면 5분 뒤 다시 확인합니다. 동일 프로세스와 여러 MCP/Monitor 프로세스의 중복 갱신 시도는 캐시 잠금으로 줄입니다.
- 인증정보가 없으면 조회 불가로 표시합니다. 동일 계정·조직으로 확인되는 마지막 사용량은 회색의 오래된 값으로 유지하며 다른 계정의 값은 재사용하지 않습니다.
- 캐시에는 사용량과 토큰/계정의 SHA-256 식별값만 저장합니다. access token, refresh token, 원문 CLI 출력은 저장하지 않습니다.
- 사용량 조회 실패는 Claude 작업 실행의 성공·실패나 인증 판정을 덮어쓰지 않습니다.

## 지원 한계와 재로그인

설치된 Claude Code 2.1.283에는 공식 `auth refresh` 명령이 없습니다. 초기화 중 CLI가 조건부로 실행하는 인증 갱신을 이용하는 best-effort 방식입니다. 네트워크, 조직 정책, CLI 설정/버전에 따라 초기화만으로 갱신되지 않을 수 있습니다. `auth status` 자체는 토큰을 갱신하지 않습니다.

갱신 후에도 인증이 거절되거나 토큰이 만료 상태이면 공식 터미널에서 `claude auth login`을 실행한 뒤 모니터를 새로고침하세요. 네트워크 장애는 잠시 후 자동 재시도합니다. CLI 구버전이 필요한 초기화 옵션을 지원하지 않으면 마지막 값/조회 불가 상태를 유지하며 CLI를 자동 업데이트하지 않습니다.

## 적용

Gateway 수정본은 새 MCP 프로세스에 적용됩니다. MCP를 재연결하세요. Monitor는 Gateway 모듈을 읽으므로 Monitor를 재시작하면 적용됩니다. 진행 중인 구현 작업을 강제 종료할 필요는 없습니다.

검증은 모의 토큰 만료/401/갱신 성공·실패/계정 변경/동시 호출로 수행했습니다. 실제 계정의 만료 시각이나 refresh token을 강제로 바꾸지 않았습니다. 실제 CLI에서는 control-only 초기화가 성공하고 모델 메시지가 없음을 확인했습니다. 실제 만료된 토큰의 자동 갱신 성공까지 확인한 것은 아닙니다.
