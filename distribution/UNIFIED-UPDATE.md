# Windows + WSL 전체 업데이트

배포 2.7.1 / Monitor 1.4.0부터 상단 다운로드 아이콘과 업데이트 창의 **전체 업데이트**가 같은 작업을 실행합니다. Gateway는 2.7.0을 유지합니다. 기존 Monitor를 이번 버전으로 먼저 업데이트한 뒤 사용하세요.

## 실행 순서

1. Windows의 현재 설치와 이 PC에 등록된 WSL 배포판을 확인합니다. 평소에는 중지된 WSL을 시작하지 않습니다. 전체 업데이트를 누르면 중지된 배포판도 시작해 설치된 Gateway가 있는지 확인합니다.
2. 모든 설치 대상의 실행 중인 작업·maintenance·업데이트 상태를 읽습니다. 한 대상이라도 실행 중이거나 확인할 수 없으면 설치를 시작하지 않습니다. Gateway가 없는 배포판은 건너뛰며 자동 설치하지 않습니다. 옛 수동 설치에 Linux 업데이터가 없으면 먼저 Linux 설치 설명에 따라 등록해야 합니다.
3. WSL Gateway를 순서대로 업데이트합니다. 모두 완료한 후 Windows Gateway·Monitor를 업데이트하고 Monitor를 다시 시작합니다. 각 설치기의 기존 유휴 검사·서명 검증·백업·복구도 그대로 수행합니다.
4. 재실행한 Monitor에 대상별 버전과 결과가 표시됩니다. Gateway가 바뀐 환경의 MCP를 다시 연결하세요.

## 실패·취소·재시작

- 일부 대상 실패를 전체 성공으로 표시하지 않습니다. 성공한 설치는 유지하고 실패한 지점에서 나머지 실행을 멈춥니다. 다시 전체 업데이트를 누르면 최신 상태를 새로 조회하여 이미 최신인 대상은 건너뜁니다.
- 준비·다운로드 중에는 취소할 수 있습니다. WSL 설치가 이미 시작됐다면 현재 설치를 강제 종료하지 않고 완료를 확인한 뒤 남은 대상 실행을 중단합니다. Windows 설치가 시작되면 종료 후 복구·재실행까지 설치기가 담당합니다.
- Monitor를 닫으면 이미 시작된 Linux 업데이터는 계속될 수 있습니다. 남은 순서는 자동 예약·재개하지 않습니다. 재실행 후 남은 작업을 확인하고 다시 눌러 주세요. 실행 응답을 잃어 설치 여부가 불명확하면 중복 실행하지 않고 수동 상태 확인을 안내합니다.
- 통합 결과는 Monitor 데이터 폴더의 `unified-update.json`에 보존됩니다. 개별 Windows 및 Linux 설치 이력·백업은 기존 위치에 유지됩니다.
- 사전 확인 이후 새 작업이 시작될 수 있으므로 각 설치기가 교체 직전에 다시 확인합니다. 여러 운영체제 전체를 한 트랜잭션으로 되돌리는 기능은 아닙니다.

## 범위와 검증

Windows 없이 사용하는 Linux PC는 `~/.local/bin/agent-acp update`를 사용합니다. 별도 원격 Linux 서버를 Windows Monitor가 업데이트하지는 않습니다. WSL이 없거나 기능이 설치되지 않은 PC는 Windows 구성요소만 업데이트합니다.

회귀 테스트는 대상별 사전 확인, 순서, Windows 최신/WSL만 구버전, 미설치/중지 배포판, 일부 실패, 중복 클릭, 취소, 결과 복원과 불확실한 실행의 재호출 방지를 확인합니다. 패키지 테스트는 임시 Windows 설치의 실제 버튼 클릭과 WSL 전송 모의 대상을 결합하며, Linux 패키지는 별도 실제 Linux 임시 설치에서 검증합니다. 사용자 설치본이나 실제 WSL Gateway를 테스트로 업데이트하지 않습니다.
